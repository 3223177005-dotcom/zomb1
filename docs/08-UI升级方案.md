# 08 · UI 升级方案（向 Mini DayZ / 僵尸毁灭工程看齐）

> 术语以 [`00-索引与术语.md`](00-索引与术语.md) 为准。本文是 UI 重构的**路线书**：
> 决策、规格、里程碑、验收标准都写在这里，改 UI 前先读。

## 一、已定的三条决策

| # | 决策 | 采用值 | 影响 |
|---|---|---|---|
| 1 | 逻辑分辨率 | **1280×720**，`stretch/scale_mode=integer` | 世界与 UI 同为 1:1 像素；窗口放大只按整数倍，不糊 |
| 2 | 版式方式 | **容器化自适应**（锚点 + 容器），不写绝对坐标 | 改分辨率不炸版；与 ZS 的 `ltrb` 绝对表**不 1:1 照搬**，只借结构 |
| 3 | 字体 | **Fusion Pixel 12px**（OFL-1.1，简体中文）+ NotoSansSC 回退 | 硬边像素；字号阶梯 12/14/16/20/24/32 |

## 二、参照物（本机现成，不随仓库分发）

`ZS_assets/ui/*.ui`（114 个）是 Zero Sievert 的 UI 场景：`inventory_player` / `inventory_chest` /
`inventory_exec_player_gear`（装备盘槽位表，带 `category` 白名单）/ `tooltip_item_*`（15 个，11 种物品类型）/
`context_menu*`（含 heal·repair·scrap·uninstall 四种二次确认）/ `crafting` / `pda_*`。
**用法：只当版式与交互规格**，图形与字体一律自行生成或使用可商用资源。

## 三、架构约定

```
scripts/ui/
  core/UiMetrics.cs        所有尺寸/字号/间距（唯一来源）
  core/UiTween.cs          统一动效（M6）
  Widgets/                 可复用控件（图标槽 / 数值条 / tooltip / 右键菜单 / 页签 / 模态 / Toast）
  Panels/                  页面级（装备盘 / 三列背包屏 / 容器列）
  Hud/                     局内 HUD（moodles / 快捷栏 / vignette）
assets/ui/theme/zombie_theme.tres   全局 Theme（9-slice + 配色 + 原生 Tooltip/PopupMenu）
```

**规则**：新控件不写死尺寸字体（走 `UiMetrics`）、不手写 StyleBox（走 Theme 或 `UiStyle`）、
不新增 `GetFirstNodeInGroup`（构造注入）、不引入全局可变状态。

## 六、验收标准（每期都跑）

```powershell
dotnet build ZombieExtraction.csproj -v q --nologo                      # 0 警告 0 错误
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check-hygiene.ps1   # 只许持平或下降
"…Godot_v4.7.2-stable_mono_win64_console.exe" --headless --path . --quit-after 150   # 主场景 0 ERROR
# 8 个自测场景（Armor / Equipment / WeaponMod / MoveRecoil / EquipNotify / TreeCollision / TreeNav / 3 个 Probe）
"…Godot_v4.7.2-stable_mono_win64.exe" --path . res://tests/GameShot.tscn     # 两档分辨率截图目视
```

**目视检查项**：文字硬边无灰边、9-slice 边角不糊、格子内图标 32px 不被拉伸、
中文无缺字（缺字会被替换成方框）、面板在 1280×720 与 1920×1080 都不溢出。

## 七、待决

- 是否把 HUD 侧栏升级为「可折叠分区」：目前整栏常驻，1366×768 笔记本上会挤。
- Tooltip 的「与已装备对比」需要先有装备对比基准（护甲 class / 武器 DPS），M2 再定算法。
- 像素字体在 14/16/20 档会有个别笔画差 1px；若不能接受，M2 把字号收敛到 12/24 两档。
